## 2. 硬性环境约束（改代码前必须知道）

1. **不能用 Electron**。本机启动即 `0xC0000005` 崩溃，换版本 / 换计划任务都无效。浮窗是原生 **WPF**，用 `csc.exe` 编译。
2. **C# 只能用 5.0 语法**（`csc` 是 .NET Framework 4.x 自带的那份）：
   - ❌ `?.`、`_ =`、字符串插值 `$""`、`nameof`、表达式体成员
   - ✅ `string.Format`、`async/await`、`dynamic`（需引 Microsoft.CSharp，本项目用反射代替）
3. **所有 `.ps1` 必须存为 UTF-8 with BOM**。PowerShell 5.1 会把无 BOM 的 UTF-8 当 GBK 读，中文全乱。
4. **路径含中文**（`<项目根目录>` 已无中文，但工作目录 `G:\酒馆相关\work` 有）。给 PowerShell / cmd 传路径要加引号。
5. **Node.js 18+ 必须存在**（服务是 Node 写的，安装包**不**内置运行时）。
6. 服务端口固定 **`127.0.0.1:4590`**，同一台机器只能跑一个实例。

## 5. 架构与数据流

```
Apple Music
    │ Windows SMTC
    ▼
scripts/smtc.ps1  ──(常驻, 默认 900ms 输出 JSON)──►  server/index.js
                                                     │
                             ┌───────────────────────┼────────────────────────┐
                             ▼                       ▼                        ▼
                     douban.js 搜索/详情       store.js 持久化            SSE /api/stream
                             │                       │                        │
                             ▼                       ▼                        ▼
                      music.douban.com          data/db.json          overlay (WPF)
                                                     ▲
                                                     │ POST /api/sync
                                              music.douban.com/j/subject/{id}/interest
```

要点：

- 浮窗启动时若检测不到服务，会 **自己 spawn** `node server/index.js`，并把子进程 stdout/stderr 持续抽干写入 `data/server.log`（不抽干会把管道写满、node 阻塞，曾导致「本地服务未连接」）。
- 连续 3 次轮询失败 → 自动重启服务（12 秒节流）。
- 浮窗通过 SSE 订阅状态，服务端 `broadcast()` 推送。

## 8. 匹配算法（`douban.js`）

### 8.1 输入归一化

- `tidyTitle()`：去掉 `- EP` / `- Single` / `(Deluxe Edition)` / `(Remastered)` 等后缀
- `interpret()`：Apple Music 常把「表演者」写成 `IVE — I've IVE`，按 `—` / `–` 拆成艺人 + 专辑

### 8.2 日文处理

- 半角片假名 → 全角（含 ﾞ/ﾟ 合并）
- 片假名 → 平假名后转罗马字（促音、长音、拗音都处理）
- `similarity()` / `artistSimilarity()` 会在「原文」和「罗马字」两组形态里取最高分
- `tidyTitle()` 去掉 `[通常盤]` `(初回限定盤)` `(完全生産限定盤)` 等
- 局限：汉字与假名之间无法互转（`桜` vs `さくら`），需要读音词典

### 8.3 外区语言兜底（MusicBrainz 桥接）

外区 Apple Music / Spotify 会把中文专辑显示成英文（「叶惠美」→ "Ye Hui Mei"），豆瓣只有中文名。`server/mb.js` 负责：

1. 英文艺人 → MB 艺术家别名（周杰倫 / 周杰伦 / ジェイ・チョウ / 주걸륜）
2. 英文专辑 → MB release-group 别名 + 条码
3. 用别名和条码生成最多 3 条补充查询，交给豆瓣搜索

触发条件（满足其一）：没把握 / 没结果 / 命中的是票数 <300 的同名再版且艺人是拉丁字母。

评分时同一条目会用「原语言」和「别名语言」两套 want 各打一次分取高者。

条码校验：只在「唯一命中且艺人相似度 ≥0.3」或「艺人 ≥0.6」时采用。

开关：`settings.mbBridge`（默认 true）。调试：`POST /api/match/test {album, artist}`。

### 8.4 查询顺序

```
艺人 + 专辑名 → 艺人 + 歌名 → 专辑名 → 歌名
```

每轮拿到候选就用 `scoreCandidate()` 打分，取全局最高。早停条件（任一候选满足即停止后续查询）：

```
艺人相似度 ≥ 0.9  且  标题相似度 ≥ 0.995（同名）  且  总分 ≥ 90
```

### 8.5 打分公式

```
总分 = 艺人相似度 × 62
     + 标题相似度 × 30
     + 同名加成（标题完全一致 +6）
     + 评分人数 min(1, log10(评价数+1)/5.5) × 12
     + 类型加成（专辑 +8 / EP +2 / 单曲 −4 / 现场 −8）
```

候选缺艺人信息时：`wArtist=0, wTitle=92`。

### 8.6 硬性门槛

- 候选人艺人相似度 < **0.35** → 拒绝（`artist_mismatch`）
- 标题相似度 < **0.45** → 拒绝（`title_mismatch`）
- `confident = 总分 ≥ 78 且 (标题 ≥ 0.5 或 艺人 ≥ 0.95)`；不 confident 时不写缓存

### 8.7 排序实测（构造数据，同艺人）

| 候选 | 分数 |
| --- | --- |
| 同名 · 119449 人 | 117.1 |
| 同名 · 3789 人 | 113.8 |
| 同名 · 88 人 | 110.3 |
| 近似标题（「叶惠美 演唱会」）· 5 万人 | 106.1 |
| 别的歌手 · 同名 · 9.9 万人 | 54.9（被艺人门槛拒） |

设计意图：**先过「艺人 + 同名」，同类里票多者胜**；票再多也不能跨歌手、不能靠「标题像」抢位。

## 9. 豆瓣交互细节（踩过的坑都在这）

### 9.1 搜索

- 主：`https://music.douban.com/subject_search?search_text=...`，页面里 `window.__DATA__ = {...}`，用**括号配对**提取 JSON（正则不可靠）
- 备：`https://www.douban.com/search?cat=1003&q=...`
- 需要访客 `bid` Cookie（`data/http-cookies.json` 持久化），否则被限流
- 请求间隔 **1.8 秒**（`throttle()`）

### 9.2 详情页

`https://music.douban.com/subject/{id}/`（带登录 Cookie 抓，否则可能 403）

解析：评分、人数、星级分布、类型、发行日期、封面。

### 9.3 ck 令牌（回写必需）

- 登录后页面上形如 `<a href="...?interest=do&amp;ck=_xDd">`
- **ck 可能是 3~5 个字符且含下划线**（如 `_xDd`）——正则必须写成 `ck=([A-Za-z0-9_\-]{2,})`
- 曾经因为写成 `{4,}` 导致同步永远报「未取得 ck 令牌」

### 9.4 回写

```
POST https://music.douban.com/j/subject/{id}/interest
Content-Type: application/x-www-form-urlencoded
X-Requested-With: XMLHttpRequest

ck=<令牌>&interest=collect&rating=4&foldcollect=F&tags=&comment=还不错
```

- `interest` 取值：`wish` 想听 / `do` 在听 / **`collect` 听过**（必须 collect）
- 音乐表单**没有** `status` 字段（读书才有）
- 返回可能是空串（视为成功）或 JSON

### 9.5 收藏分页（导入「听过」）

```
GET https://music.douban.com/people/{uid}/collect?start=N&type=music
```

- 每页 **15 条**
- 结构：`class="item comment-item"` → `subject/{id}/`、`<em>标题</em>`、`class="intro"`（表演者 / 日期 / 类型 / 介质 / 流派）、`ratingN-t`（星级）、`<span class="date">`（打分日期）、下一个 `<li>` 是短评
- ⚠️ 短评在日期 `<li>` **之后**的那个 `<li>` 里，正则写错会把日期一起吞进短评
- 翻页看 `<link rel="next" href="...start=NN">`

### 9.6 播放器来源与兜底

- 正常路径：Windows SMTC（`scripts/smtc.ps1`）→ 只在该播放器上报时有效
- 兜底路径：SMTC 没有会话时，读播放器**窗口标题**（网易云「歌名 - 艺人」），输出 `via:"window"`
- 网易云 3.1.41 实测不注册 SMTC（配置 `SMTCEnable=true` 也没用），依赖兜底
- 只有歌名时，`server/netease.js` 用 music.163 的公开搜索接口补出所属专辑，再交给豆瓣
- 排查工具：`scripts/smtc-list.ps1`（列会话）、`检查播放器.bat`（给判定与原因）

### 9.7 限流

- 大量请求后豆瓣会返回**空壳页**（`window.__DATA__` 缺失）或搜索结果为空
- 现有应对：1.8 秒节流、缓存、`bid` 持久化、失败重试（12s/30s/90s/180s/300s/600s）、导入分批

## 10. 账号 / 导入 / 同步流程

### 10.1 绑定

1. 设置 → 豆瓣账号 → **「打开豆瓣」** → 用系统默认浏览器打开 `https://www.douban.com/`
   （实现：读注册表 `UrlAssociations\https\UserChoice` 拿 ProgId → 取 exe → `exe --new-window <url>`）
2. 用户在浏览器登录
3. F12 → Network → 刷新 → 任意 douban.com 请求 → Headers → Cookie → 复制值
4. 回到设置点 **「从剪贴板读取」**：解析 `bid` / `dbcl2`（还原 `dbcl2` 的引号）→ 保存 → `POST /api/douban/verify` 验证并记住昵称
5. 若只有 Cookie 没有昵称（例如走「手动粘贴 → 保存」），打开设置页会自动补验证

### 10.2 导入「听过」

- 入口：设置页「导入我在豆瓣听过的评分 →」或 `导入豆瓣收藏.bat`
- 分批（每批 ≤20 页），游标存 `settings.importCursor`，中途可停、下次续；拉完归零
- 导入的条目 `source: "douban"`、`synced: true` → 浮窗上直接显示为「已同步」，避免误覆盖
- 当前状态：**1692 条**已导入

### 10.3 同步

浮窗点「同步」→ `POST /api/sync` → 抓详情页拿 ck → POST interest（`interest=collect`）→ 本地标记 `synced=true`。

### 11.1 浮窗

- 无边框、置顶、半透明；**只能拖 header**（整窗 `DragMove` 会吞掉按钮点击）
- 顶栏：`播放器名 · 当前曲目`（曲目与专辑同名时省略曲目）+ 播放状态 + 「⋯」
- 元素：封面、专辑名、艺人 · 年份 · 流派、豆瓣分（大号）、豆瓣星、人数、星级分布条、我的星、短评框、同步按钮、进度条
- 「⋯」（`BtnManage`）与窗口右键都打开同一个菜单；按钮点击用 150ms 延迟弹出（否则会被同一次点击误触第一项）
- 拖动只绑在顶栏/封面/标题上，且排除「⋯」区域
- 右键菜单（`MiManage` / `MiTodo` / `MiSync` / `MiTop` / 缩放 / `MiExit`）：
  - 「历史与设置…」→ 打开设置窗口
  - 「把评分写入豆瓣」→ 同步
  - 「窗口置顶 ✓」→ 切换置顶
  - 「退出」
  - 菜单皮肤跟随当前皮肤，XAML 占位符 `{{BG}} {{TEXT}} {{HOVER}} {{LINE}} {{BORDER}} {{SHADOW}}`
- 未匹配：「豆瓣没找到这张 · 右键「手动绑定」」
- 无播放：「在 Apple Music 里播放一张专辑即可」

### 11.2 皮肤

| 皮肤 | 底色 | 主色 | 说明 |
| --- | --- | --- | --- |
| `neumorphic` 新拟物 | `#e0e5ec` | `#6d5dfc` | 双阴影浮雕 |
| `glass` 玻璃拟态 | `#0b1322` + 径向光斑 | `#e4b863` 香槟金 | 8% 白色玻璃层 |

两套 XAML **元素名完全一致**，同一份 C# 驱动；切换皮肤 = 销毁窗口 → 设 `ShutdownMode.OnExplicitShutdown` → 换 XAML 重建 → `app.Run()`。

### 11.3 设置窗口

四个标签页：**收听史 / 待评分 / 手动绑定 / 设置**。

- 收听史：历史列表（封面、标题、艺人、时间、我的星）
- 待评分：浮窗「稍后再评」存下来的专辑。每行两栏：
  - 上：标题 / 艺人 · 来源 · 加入时间 | 星级 | 移除
  - 下：评语输入框 | **同步**
  - 点星只写本地；点「同步」才写入豆瓣「听过」，成功后自动从列表消失
  - 未绑定豆瓣的显示「去绑定」，跳到手动绑定并带上标题
- 手动绑定：搜索框 → 结果列表 → 点选绑定
- 设置：播放器来源（自动 / Apple Music / Spotify / 网易云 / QQ 音乐）、界面皮肤（新拟物 / 玻璃拟态）、豆瓣账号（打开豆瓣 / 从剪贴板读取 / 解除绑定 / 导入我听过的评分）、手动粘贴 Cookie、保存

单实例信号：`--settings` / `--login` 通过命名 `EventWaitHandle` 通知已运行实例。

## 12. 安装包

- 产物：`dist\豆瓣正在听-安装包.exe`（约 183 KB，单文件）
- 技术：自写 C# WinForms 安装程序（机器上没有 Inno Setup / NSIS）
- 载荷：`installer/payload.zip` 以资源名 `payload.zip` 内嵌
- **不写临时文件**：直接从资源流 `ZipArchive` 解压到目标目录（曾被安全软件拦截 Temp 写入）
- 默认目录：`%LOCALAPPDATA%\Programs\DoubanNowPlaying`（免管理员）
- 盘符根自动补子目录：`D:\` → `D:\DoubanNowPlaying`
- 装前写入探测；失败给出换目录 / 管理员运行的提示
- 快捷方式：开始菜单「豆瓣正在听」文件夹（主程序 / 管理 / 卸载）+ 桌面
- 注册表：`HKCU\...\Uninstall\DoubanNowPlaying`（`DisplayVersion=1.1.3`）
- 卸载：`卸载.bat`（纯 ASCII）→ 复制 `uninstall.ps1`（UTF-8 BOM）到 TEMP 执行 → 杀主程序 + 按目录匹配杀 `node.exe` + 删快捷方式/注册表/目录
- 静默：`/S`，可加 `/D=路径`；失败写 `%TEMP%\dnp-setup-error.log` 并返回 1

**打包时排除**：`data/`（Cookie、评分、历史、缓存、日志）、源码 `.cs`、`build.ps1`、`../screenshots/`。

## 13. 已知问题与坑

| 问题 | 现状 / 原因 |
| --- | --- |
| 豆瓣限流 | 大量抓取后搜索返回空壳。已加节流、缓存、长退避；导入时最明显 |
| 浏览器窗口不到前台 | 从后台进程调用 `SetForegroundWindow` 被 Windows 前台锁拦截；已改成默认浏览器 `--new-window` 打开新窗口 |
| 端口互斥 | 4590 只能一个实例；安装版与开发版同时运行会互相顶替（新实例会「复用」旧服务，可能读到另一份空数据） |
| 卸载残留 | 早期只杀主程序不杀 node，已修（按安装目录匹配 node 命令行） |
| 装到盘符根 | 已自动加子目录 |
| `D:\` 不存在却可选 | 安装界面不校验盘符是否存在，会在 `Directory.CreateDirectory` 时报错 |
| 中文 bat 编码 | 卸载逻辑改走 PowerShell（UTF-8 BOM），bat 保持纯 ASCII |
| csc 版本旧 | 不能写现代 C# 语法 |
| 评语/评分串专辑 | 已修：切歌时先把未保存评语写回原专辑（`_commentSubjectId`） |
| 历史删除失败 | 已修：接口此前不存在 + 字段名不匹配（`id` vs `key`） |
| 空字段冲掉标题 | 已修：`/api/rating` 只在字段非空时覆盖 |
| 导入短评带日期 | 解析已修；存量 719 条脏数据已清理 |

## 16. 给接手模型的建议

1. 先读 `CHANGELOG.md` 了解最近改动，再读本文件。
2. 改匹配逻辑只动 `server/douban.js` 的 `scoreCandidate()`；改完把 `store.js` 的 `CACHE_VERSION` +1，否则旧缓存仍生效。
3. 改浮窗 UI 要**同时改两套 XAML**，且元素 `x:Name` 不能变（C# 按名字取控件）。
4. 改完 C# 必须重新 `overlay\build.ps1`，否则跑的还是旧 exe。
5. 改完服务端要重启 node（杀掉即可，浮窗 20 秒内自动拉起）。
6. 任何要发给别人的东西，先确认 `data/` 没被打进去。
