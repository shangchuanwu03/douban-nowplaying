**修复「同步后豆瓣只有星没有评语」**

原因：浮窗的「同步」按钮只发 `subjectId`，服务端再去读本地记录里的评语。而点同步会让评论框失焦，触发一次**异步保存**——两个请求抢跑，同步先到、保存后到，服务端读到的是还没保存的空评语。

修法（三处配合）：

1. 浮窗同步前**先把星和评语写进本地**（`await`），再发同步请求
2. 同步请求**直接带上 `rating` / `comment`**，服务端优先用请求里的值，不再依赖落盘时序
3. 服务端同步前把这份内容固化到本地记录，避免出现「豆瓣有评语、本地没有」

待评分里的同步按钮同样改为带评语提交。

实测：给《Debut》(1394554) 同步一条测试评语 → 豆瓣专辑页立刻出现；再同步回原评语 → 已恢复。

## v1.3.2 — 2026-11-23 19:4x

**修复「收听史删除失败」**

- 原因一：界面调用 `POST /api/history/delete`，但服务端**从来没实现过这个接口**（只做了 GET `/api/history`），一律返回 `no such api`
- 原因二：界面按 `id` 字段删除，而历史记录内部用的是 `key`，即使接口存在也会删不到
- 修法：服务端 `/api/history` 输出时补 `id`（与 key 同值）；新增 `POST /api/history/delete {id}` 与 `store.removeHistory()`
- 校验：删不存在的 id 返回 `{ok:false}`，删已存在的返回 `{ok:true}` 并真的从列表消失

## v1.3.1 — 2026-11-23 19:2x

**修复「已评分专辑显示错的评分/评语」**

三个独立原因，都已修：

1. **评语跟错专辑**（浮窗）
   - 原因：评论框里未保存的文字会在失焦时保存，而保存用的是「当前专辑」的 id。切歌后失焦，就把上一张的评语（连同当时的星级）写到了新专辑上。
   - 修法：记录「评语属于哪张专辑」（`_commentSubjectId`），切歌时先把未保存内容写回**原本那张**，再刷新成新专辑的内容。

2. **专辑名被冲成空白**（服务端）
   - 原因：`/api/rating` 在浮窗打分时只传 `subjectId/rating/comment`，服务端却把空字符串的 `title/artist/cover` 一起合并进去，把导入时存好的标题覆盖掉。
   - 修法：只在字段非空时覆盖。已回填 3 条被清空的标题（Irony / True Blue / 慢花志）。

3. **719 条评语是日期**（历史数据）
   - 原因：早期导入脚本的正则把「打分日期」当成了短评（如 `2024-09-27`），解析器此前已修，但存量数据没清。
   - 处理：清除 719 条纯日期评语，现存 594 条真实短评。
