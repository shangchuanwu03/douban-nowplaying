## 3. 新增文件

### `<项目根目录>\server\text.js`（192 行）

文本比较的统一口径，供 `douban.js` 与 `applecatalog.js` 共用，避免两边对「繁简 / 括号 / 斜杠」的判断不一致。

- `toSimplified(s)`：繁 → 简，内置约 400 组常用字对照（`T2S_PAIRS`），只影响比较与检索，不改界面显示
- `norm(s)`：小写、全角转半角、去标点空白，最后折叠繁简
- `titleVariants(title)`：拆「中文 / English」、拆 `(Ye Hui Mei)` 括号补充、拆 `- 副标题`，返回所有候选写法
- `similarity(a, b)`：字符二元组相似度
- `artistTokens(name)` / `artistSimilarity(want, cand)`：艺人拆词与相似度（保留原有的包含、分词命中规则）

### `<项目根目录>\server\applecatalog.js`（264 行）

Apple 目录桥（iTunes Search API，免 key），把外区英文名换回中文名。

- `SEARCH_STORES = ['tw','hk','jp','sg','us','cn']`：台湾 / 香港店中文目录最全，日本店英文别名收录最好
- `rankCandidate()`：`rankBonus = max(0, 30 - idx*6)` + `titleSim*40` + `artistSim*30` − 15（名字含 Single/EP/Live 时降权）
- 同一条作品在不同店会写不同艺人（`周杰倫` / `Jay Chou`），按 `collectionId` 合并 `artistNames`，打分取最像的一个
- 对 top5 候选批量 `lookup?id=...&country=cn` 换简体名；老目录在 cn 店没有映射时回退到候选原名 + 繁转简
- `localize(album, artist)` → `{ album, artist, albums[], artists[], titleSim, artistSim, confidence, itunesId, storefront, candidates[] }`；失败 / 不需要时返回 `null`，主流程不受影响
- 缓存：`cache.json` 的 `catalog` 段，命中存 60 天、未命中存 3 天，`CATALOG_VERSION = 1`；进程内还有 in-flight 去重

## 6. 第 2 项：外区英文名怎么匹配（重点）

### 为什么不是「识别条形码」

- Windows SMTC 只暴露 title / artist / album / 进度，**没有 UPC / 条形码**
- 豆瓣详情页确实有「条形码」字段，但只能「已知条目 → 查条码」，不能「已知条码 → 查条目」（豆瓣搜索不索引条码）
- 所以条码只能做成缓存：解析出条目后把 `条形码 → subjectId` 记进 `cache.json`，将来若播放器能提供条码就能直接命中；当前不影响主流程

### 实际方案：Apple 目录跨区译名桥

```
播放器报 "Fantasy" / "Jay Chou"
        │
        ▼
iTunes 台湾 / 香港 / 日本店搜索「Jay Chou Fantasy」
        │  同一条作品在不同店有不同写法：周杰倫 / Jay Chou、范特西 / 范特西
        ▼
取 collectionId → lookup?country=cn 换简体名 + 候选里的其他写法
        │
        ▼
得到「范特西」「周杰伦」→ 用它们重新搜豆瓣 → 正常打分
```

- 只在前一轮「不够自信」时才触发本地化，最多再加 2 条豆瓣检索（约 +4 秒），不会拖慢正常识别
- 打分时把本地化名字作为 `altAlbums` / `altArtists` 一起取最高分，**但只取最像主专辑的那一个中文名**，避免把「依然范特西」当成「范特西」
- 豆瓣详情的「又名」和这次换出来的中文名都会写进别名缓存（`cache.json` 的 `alias` 段，180 天），下次同一个英文名直接命中，不再检索

## 7. 第 3 / 4 / 5 项的实现细节

### 播放器识别（第 3 项）

模式与 AppUserModelId 正则：

| 模式 | 正则 | 说明 |

- 实测：`smtc.ps1 -Once -Match spotify` 输出 `app: null`，`-Match applemusic` 输出 Apple Music 会话，过滤生效

### 窗口缩放（第 4 项）

- 窗口可拖右下角改变宽度（`ResizeMode="CanResizeWithGrip"`，高度仍随内容自适应，最小宽度 400）
- 整体缩放：**Ctrl + 滚轮** 以 0.05 步进在 85% ~ 140% 之间调整；右键菜单也有「放大 / 缩小 / 恢复默认大小」
- 实现：对窗口内容做 `LayoutTransform` 缩放，窗口宽度 = `460 × scale`，位置始终贴住右下角（右边缘、底边不动）
- 缩放值 600ms 防抖后写入 `settings.overlayScale`，下次启动恢复

### 收听史删除（第 5 项）

- 每条历史右侧有「删除」：**第一次点变成「确认删除」（3 秒后自动还原），第二次点才真删**
- 删除调用 `/api/history/delete`，服务端按 `id = key@startedAt` 精确删除，删除后列表自动刷新
- 只删本机收听记录，不影响豆瓣上的评分

## 8. 这次踩到并修掉的坑

1. **编辑 `.ps1` 会把 BOM 弄丢**。PowerShell 5.1 会把无 BOM 的 UTF-8 当 GBK 读，中文注释里的字节被解析成引号，报 `Unexpected token '}' in expression or statement.`。已用 Node 补回 `EF BB BF`，并用 `Parser::ParseFile` 校验通过（`PARSE OK`）。**以后每次改 `.ps1` 都要重新检查前三字节。**
2. **`WebClient.DownloadString` 在这台机器上按系统 ANSI 代码页解码**：`{"doubanCookie":"已设置",...}` 里的「已设置」把后面的引号「吃掉」，JSON 解析报 `传入的对象无效，应为“:”或“}”`，导致浮窗读不到 `skin`，皮肤回退成新拟物。已改成 `DownloadData` + `Encoding.UTF8.GetString`，并在 `app.log` 里加了 `settings: skin=... scale=...` 便于排查。
3. **csc 覆盖 exe 前必须先退出浮窗**，否则报 `error CS0016: 未能写入输出文件 ... 另一个程序正在使用此文件`。顺带一个教训：不要用大范围杀 powershell 进程的方式清理采集器，曾导致命令运行器本身退出；要按镜像名或端口 PID 精确杀。
4. **管理页的 ★ 会落到彩色 emoji 字体**，`Foreground` 不生效（未打分也显示成金色）。已给星标指定 `FontFamily("Segoe UI Symbol")`（源码已改，**还没重新编译**）。
5. **切换识别来源时旧采集器退出会误清新进程**，导致重复重启。已用 `this.child !== child` 代际守卫解决。
6. **切换播放器模式后 `resolving` 一直是 true**（界面会显示「正在查豆瓣…」）。已在清空播放状态时把 `resolving` 置回 false。
